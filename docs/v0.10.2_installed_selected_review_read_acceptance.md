# v0.10.2 Installed Selected-Review Read Acceptance

Classification: **required exact-wheel acceptance for #414**.

## Purpose

Issue #414 optimizes the `Selected Student Review` redraw without weakening
Quillan's canonical-state freshness or routed-evidence integrity checks. The
optimization is deliberately redraw-scoped: one immutable assignment review
read context may be reused while composing one screen, but no cache survives a
teacher action, navigation command, export, cancel, or child-workflow return.

## Source read-amplification acceptance

The deterministic source gate builds a representative assignment with:

- 30 roster students;
- valid submission and review records across the class;
- representative current, stale, metadata-free, and missing feedback states;
- four persisted routed observations per student;
- 120 actual routed evidence files; and
- strict retained-source provenance and routed-evidence SHA-256 metadata.

For one ordinary Selected Student Review redraw, the acceptance requires:

```text
assignment-context loads:          1
roster loads:                      1
strict observation grouping:       1
routed-evidence verify/hash calls: 120
assignment submission rebuilds:    0
scan-review discovery calls:       0
workspace writes:                  0
```

The 120 verification calls are intentional. Issue #414 removes redundant
assignment-wide passes; it does not replace byte reads or hashes with mtime,
size-only, persistent-cache, or trust-on-first-read shortcuts.

## Installed exact-wheel acceptance

`scripts/verify_installed_selected_review_reads.py` runs from outside the source
checkout. The v0.10.2 candidate validator invokes it once with the exact
candidate wheel installed against Core 0.6.2 and once against Core 0.6.3.

The installed probe creates a 30-student canonical assignment and proves:

- installed Quillan and Core imports are not source-shadowed;
- the selected-review root performs one assignment load;
- the selected-review root performs one roster load;
- the selected-review root performs one strict observation-grouping pass;
- legacy `list_assignment_submission_status(...)` is not used by the redraw;
- legacy public student-status/navigation builders are not used by the redraw;
- routine queue/navigation does not invoke scan-review diagnostics; and
- rendering the selected-review root does not modify workspace bytes.

## Preserved behavior

The following remain intentionally unchanged:

- exact identifier and canonical-path validation;
- routed-evidence file existence and link/junction safety;
- routed-evidence size and SHA-256 verification;
- retained-source provenance validation;
- fail-closed dashboard behavior when strict observation discovery fails;
- fresh queue/navigation composition after every teacher action;
- assignment, submission, review, feedback, publication, and diagnostic schemas;
- Core routing/publication/module-operation contracts; and
- teacher authority over review and feedback.

## Physical boundary

This issue changes read composition only. It does not change printable-response
generation, route registration, scan intake, evidence materialization, or
physical page interpretation. The historical v0.10.0 physical acceptance
therefore remains applicable unless a later diff crosses that boundary.

Passing this document's automated gates does not grant release authorization.
