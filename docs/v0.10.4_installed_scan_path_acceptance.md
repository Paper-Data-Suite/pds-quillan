# Quillan v0.10.4 Installed Scan-Path Acceptance

Classification: **historical Issue #416 exact-wheel acceptance contract for released Quillan v0.10.4**.

## Purpose

This acceptance closes the Quillan side of the Core #226 release blocker. It
proves that the exact Quillan v0.10.4 candidate wheel can consume fresh Core
0.6.4 retained-source identity and historical Core 0.6.3 retained-source
identity under meaningful Windows path pressure.

## Core 0.6.4 handoff candidate

```text
Core commit: 2e47734  refresh released consumer compatibility

pds_core-0.6.4-py3-none-any.whl
SHA-256 201e651f4b9aad0bfeb1565b37f425982513f2fb616b86a8835a10f4dcd7db62

pds_core-0.6.4.tar.gz
SHA-256 8faa892a1e665d3d7dea1ad800ca5e03ffa235ef3b0fda224e8e96f5664aae6e
```

The release validator authenticates the exact Core wheel. The sdist hash is
retained as handoff evidence.

## Required installed evidence

The final v0.10.4 release-candidate run must build one exact Quillan wheel,
install it with the authenticated Core 0.6.4 candidate in an isolated
environment outside both source checkouts, pass `pip check`, and execute
`scripts/verify_installed_issue416_scan_paths.py`.

The harness must report PASS for fresh Core 0.6.4 provenance/PDF processing,
historical Core 0.6.3 provenance/PDF/image processing, bounded new routed
evidence, and legacy routed-evidence reads. `migration_or_rename` must be false.

The historical PDF must exercise substantial deep-path pressure. The new
routed-evidence filename must remain within
`ROUTED_EVIDENCE_FILENAME_MAX_LENGTH`. On Windows, `LongPathsEnabled` may be
read before and after qualification but must not be changed.

## Pre-release handoff evidence

Before the 0.10.4 version bump, branch commit `cdbf477` was built temporarily as
Quillan 0.10.3 only to characterize the repaired behavior against the exact
Core handoff wheel. That installed run passed with:

```text
historical_pdf_path_length: 321
new_evidence_filename_length: 40
new_evidence_filename_max: 41
long_paths_policy_before: 1
long_paths_policy_after: 1
migration_or_rename: false
status: PASS
```

This is development handoff evidence, not final v0.10.4 release evidence. The
final release gate repeats the contract against the exact v0.10.4 candidate
wheel bytes.

## Compatibility

No workspace migration is required. Runtime dependency remains
`pds-core>=0.6.2,<0.7`. Core 0.6.4 is a qualification endpoint for #416, not a
new runtime floor.
