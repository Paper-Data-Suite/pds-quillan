# v0.10.0 Installed Class-Set Acceptance

Classification: **active #393 acceptance contract**.

## Purpose

This acceptance proves that the teacher-workflow milestone completed by
#380–#392 works as one installed Quillan v0.10.0 candidate rather than only as
source-level feature tests.

The candidate must be a normal noneditable installation outside the checkout.
Source `PYTHONPATH` shadowing is forbidden.

## Exact-artifact rule

Build one exact pair:

```text
quillan-0.10.0-py3-none-any.whl
quillan-0.10.0.tar.gz
```

Record byte length and SHA-256. Reuse the same wheel against Core 0.6.2 and
0.6.3 and for physical acceptance. Rebuilding invalidates evidence tied to the
previous hash.

## Independent installed identities

Verify separately:

```text
console_scripts
  quillan = quillan.cli:main

paper_data_suite.modules
  quillan = quillan.pds_module:get_module_profile

paper_data_suite.publication_producers
  quillan = quillan.pds_publication:get_publication_producer_profile

paper_data_suite.module_operations
  quillan = quillan.pds_operations:get_module_operations_profile
```

The operations profile must expose both attention and readiness. Discovery of
one contract is not evidence that another works.

## Synthetic class-set matrix

Use only synthetic identities and writing. Exercise at least:

```text
printable/routed evidence
plain paper
awaiting assembly
review not started
requirements pending
observations pending
ratings pending
feedback pending
feedback export missing
feedback export stale
completed/exported
```

Where naturally supported, include scan-review and post-dispatch attention.

Durable Quillan state should be created through production APIs/CLI/menu paths,
not handwritten merely to satisfy expected assertions.

## Teacher-workflow acceptance

Prove installed behavior for:

```text
safe assignment copy
review-configuration preset
recent class/assignment context
deterministic review queue
previous/next student
next student needing review
Continue Review
compact routine review
batch feedback export
class completion/export status
Share Results
local diagnostics
attention
readiness
```

Teacher authority remains explicit. Do not infer ratings, applicability,
minimum-requirement outcome, feedback, completion, risk, priority, plain-paper
state, or publication.

## Publication boundary

Share Results may guide explicit Academic Work Registration, manifest
generation, publication, and supersession, but review completion and feedback
export are not publication authorization. Quillan does not import Meridian or
calculate downstream Grade/proficiency policy.

## Routing and Suite boundary

Core owns PDS2 ownership resolution and dispatch. Prove a Quillan route plus a
foreign synthetic route remain isolated, including when the foreign module is
absent.

Unified mixed-paper intake UI remains Paper Data Suite work. Quillan v0.10.0
interoperability does not claim that Suite workflow is already implemented or
that a current Suite release manifest endorses this candidate.

## Privacy and diagnostics

Acceptance output must not expose real student data, synthetic writing bodies,
teacher feedback bodies, private notes, raw QR payloads, or unnecessary
absolute workspace paths. Diagnostics remain local and do not determine
attention or readiness.

## Core endpoints

Authenticate and qualify:

```text
Core 0.6.2
Core 0.6.3
```

The runtime dependency remains exactly `pds-core>=0.6.2,<0.7`.

## Release-edge binding

After the installed application, producer lifecycle, module operations, and
class-set acceptance have passed, `verify_installed_release_edges.py` binds the
remaining release edges without replacing those earlier authorities.

It verifies:

```text
exact console/application entry point
exact Core routing entry point/profile
exact publication-producer entry point
exact module-operations entry point
canonical two-revision publication/supersession lifecycle
canonical withdrawal of the final synthetic series head
registered foreign + Quillan route ownership isolation
absent foreign-module failure isolation
no fallback of foreign work to Quillan
Quillan dispatch still succeeds after foreign failure
privacy-minimal local diagnostic output
```

The mixed-routing acceptance wraps only the installed Quillan route handler
while preserving Quillan's real registration validator and advertised Core
routing profile. The preceding installed full workflow remains the authority
that the real Quillan handler itself successfully handled PDS2 returned-paper
routes.
