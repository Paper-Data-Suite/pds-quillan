# v0.10.1 Installed Batch Feedback Acceptance

Classification: **required exact-wheel acceptance for #412**.

The candidate validator installs the exact
`quillan-0.10.1-py3-none-any.whl` outside the source checkout against both
supported Core qualification endpoints. Installed imports and the console
entry point must resolve from that environment, never this repository.

The synthetic full workflow creates two roster students with current canonical
feedback PDFs, then proves:

- `assemble-feedback-batch --whole-class --output both --duplex-safe --dry-run`
  reports both students ready and creates no `feedback_batches/` directory;
- the installed console script executes the same command with `--yes`;
- exactly one new batch directory contains the print packet and sharing ZIP;
- packet text begins with students in canonical roster order;
- the ZIP has one safe PDF name per included student in roster order;
- every ZIP member equals its canonical source PDF bytes;
- source PDFs, `submission.json`, and `review.json` remain byte-identical;
- snapshots taken immediately before the dry run and immediately after assembly
  prove byte/structure equality for Academic Work registration, Academic Result
  manifest, publication record/head, withdrawal/supersession, and publication
  catalog state. This isolates #412 from legitimate state created by other
  acceptance phases while proving assembly introduces no such side effects.

The existing installed application, producer, operations, class-set, and
release-edge checks remain required. This patch does not repeat physical-paper
acceptance unless the final diff unexpectedly changes a physical boundary.

Final qualification records the exact wheel and sdist filenames, byte lengths,
SHA-256 values, installed origins, Core endpoints, and release commit before an
owner authorizes release.
